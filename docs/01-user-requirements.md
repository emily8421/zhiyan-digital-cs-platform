| Q-ID | 质量需求 | 阶段 | 说明 |

| Q-001 | 响应可解释 | [P1] | 回答需标明依据类型：知识库 / 规则 / Mock / 转人工。 |

| Q-005 | 本机可跑 | [P1] | Demo 必须在当前 Windows 开发机可运行；Docker / DB 可延后验证。 |
| Q-006 | 隐私最小化 | [P1] | 样例数据必须标明 Mock，不引入真实客户资料。 |

## 3. 需求边界

- U-001~U-012 是需求全集草稿，是否全部进入 Phase1 以 `docs/03-prd.md` 路线图为准。
- 订单 / 项目进度查询在 Phase1 只能使用 Mock 适配层；真实业务系统接入属于 Phase3。
- 飞书机器人在 Phase1 仅作为适配接口或 Mock 通知演示；真实外部调用需人工确认联网与凭据边界。
- 若后续启用 LLM，必须新增需求补充：事实来源、成本上限、失败兜底、审计日志和人工复核。

## 5. 人工确认记录

1. `zycs` / `zycs_` 已确认为项目缩写与数据库表前缀。
2. Phase1 前端框架已确认采用 React + Vite + TypeScript。
3. Phase1 已确认不真实调用飞书机器人，仅记录 Mock payload。
4. Docker / PostgreSQL / pgvector 已确认不强制纳入 Phase1 本机演示，默认可 Mock / 本地临时数据降级。
5. Phase1 已确认不启用 LLM，仅使用规则 / 知识 / Mock 数据与转人工兜底。
