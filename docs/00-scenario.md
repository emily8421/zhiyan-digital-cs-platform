## 1. 背景与问题

古镇产业带及类似中小企业大量依赖微信群、销售个人经验和人工盯群维护客户沟通。调研输入显示，客户消息、询盘、售后、项目进度、订单交期等信息分散在群聊、个人经验和外部业务系统中，老板难以掌握当天发生了什么，员工也难以保持统一口径。

当前痛点包括：

- **漏回与响应空窗**：高峰期、夜间和节假日客户消息容易无人响应。
- **知识不沉淀**：产品参数、售后规则、项目流程依赖老员工经验，新员工难以快速准确回答。
- **售后风险失控**：退换货、投诉、赔付、交期等问题如果员工随意承诺，容易引发客诉或舆情。
- **进度查询成本高**：订单 / 项目进度依赖 ERP、OA、飞书项目或人工同步，客户重复追问。
- **老板缺少总览**：老板不想逐群翻消息，但需要知道关键客户、未跟进事项和知识缺口。

成功后的变化是：客户先通过轻入口获得有依据的自助响应，员工只处理需要人工判断的事项，运营人员持续沉淀知识，老板能看到客户沟通的可追溯摘要。

## 2. 目标用户与角色

| 角色 ID | 角色 | 目标 | 痛点 | 成功标准 |
|---|---|---|---|---|
| R-001 | 外部客户 / 采购商 / 品牌商 | 快速得到产品、方案、售后或进度答复 | 不知道找谁、反复追问、等待人工 | 能在 H5 中得到明确答复或转人工结果 |
| R-002 | 销售 / 客服 | 减少重复回答，及时接收需人工跟进事项 | 消息多、知识散、容易漏跟 | 接到结构化留资、风险和缺口通知 |
| R-003 | 项目经理 / 售后人员 | 接住项目进度、技术资料、维保与投诉问题 | 客户问题跨部门，判断成本高 | 系统先分流，复杂问题再由对应人员处理 |
| R-004 | 老板 / 运营负责人 | 看到当天客户沟通、未结案事项和风险 | 群太多，无法逐个查看 | 控制台或日报展示关键摘要 |
| R-005 | 知衍运营人员 | 为客户配置场景包、知识库、Mock 数据和规则 | 不同客户业务形态差异大 | 产品型 / 项目型场景能复用配置 |

## 4. 当前 Phase 场景边界

Phase1 是本机 Demo，不是生产 MVP。当前只要求用 Mock 数据演示端到端价值闭环：客户 H5 提问、后端按场景包和知识库回答、必要时转人工 / 记录缺口、员工侧 Web 控制台查看状态、通知适配层可用 Mock 或默认关闭方式演示。

当前明确不做：真实企业微信会话存档、真实飞书组织数据、真实业务系统查询、真实客户数据处理、外部付费 API / LLM 调用、本地大模型推理、生产部署和多租户计费。
