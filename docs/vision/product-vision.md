## 1. 产品定位

知衍数字客服统一平台面向古镇产业带及类似中小企业，解决“靠微信做生意、靠人盯群”的客户沟通困境。平台以 H5 对话、知识库问答、场景包、Mock 业务查询、员工通知和运营看板为基础，把售前咨询、售中进度、售后规则与知识缺口沉淀成可演示、可迭代的数字客服流程。

产品的核心价值不是替代全部人工，而是先把高频、低风险、可规则化的问题稳定接住；遇到高风险、无依据或需要业务判断的问题，明确转人工并留下可追溯记录。长期形态可扩展到公众号、小程序、客户自有系统嵌入、真实 CRM/ERP/OA/飞书项目集成和多租户运营平台。

## 3. 目标体验

- **客户侧轻入口**：Phase1 使用 H5 对话页，客户扫码即用；不依赖企业微信客户群自动回复。
- **回答有依据**：系统只能基于知识库、规则、场景包或 Mock 数据回答；无依据时说明无法确认并转人工。
- **风险可兜底**：投诉、赔付、合同、价格、交期承诺、隐私数据等高风险问题不自动承诺。
- **运营可追踪**：每次答不上、转人工、Mock 查询、通知发送都能留下记录，便于复盘。
- **老板看结果**：用日报 / 控制台汇总“问了什么、答了什么、谁还没跟”。

### 4.1 知衍差异化能力（C 层）

> 知衍相对通用数字客服产品的独特价值，多数源自古镇中小企业"达不到通用解法默认起点"（见 `SRC-IN-002`）。

| 能力 ID | 能力 | 差异化价值 | 来源 |
|---|---|---|---|
| PV-DIFF-001 | 兼容个人微信现实的低门槛入口 | 规避企业微信认证门槛与存档接口费持续成本 | SRC-IN-002、SRC-IN-004 |
| PV-DIFF-002 | 代结构化知识（替客户从个人经验整理成知识库） | 解决客户"知识未结构化"起点缺口（服务型差异化） | SRC-IN-002 |
| PV-DIFF-003 | 免 / 低维护交付（配置后客户基本不用动手） | 解决客户"无专职 IT"起点缺口（服务型差异化） | SRC-IN-002 |
| PV-DIFF-004 | 场景包复制策略与成本分级 | 区分"换客户低成本"与"新场景包接近重做"（见 §4.4） | SRC-IN-003 |
| PV-DIFF-005 | 不编造兜底 + 高风险转人工 | 强化 PV-CAP-006 的责任边界，AI 不替人决策 | 现有 / SRC-IN-002 |
| PV-DIFF-006 | 老板看结果（日报 / 控制台摘要） | 适配草根老板"看具体效果"的认知模式 | SRC-IN-002、SRC-IN-004 |
| PV-DIFF-007 | 古镇交付与定价适配 | 阶梯 / 买断适配古镇采购心理（定性，详细商业策略另立文档） | SRC-IN-004 |

### 4.3 明确不做能力（D 层）

> 与知衍定位冲突或受合规 / 资源限制排除的能力。区分"明确不做"与"长期视条件评估"。

| 能力 ID | 能力 | 不做原因 | 长期定位 |
|---|---|---|---|
| PV-NOT-001 | 真实企业微信会话存档 / 监控链路 | 强依赖企业微信认证 + 客户同意，与个人微信现实冲突 | 长期视合规条件评估，非近期目标 |
| PV-NOT-002 | 个人微信群机器人自动对外回复 | 合规风险，已被证伪排除 | 明确不做 |
| PV-NOT-003 | 高风险售后自动裁决 | AI 不替人决策 | 明确不做 |
| PV-NOT-004 | 本地大模型训练 / 生产规模向量索引 | 本机资源禁止 | 明确不做 |
| PV-NOT-005 | Boss 特助（SCRM / 会话存档）产品化方向 | 资源聚焦拆分；技术上可融合，非技术限制 | 非近期，视资源再评估 |

### 4.4 场景包复制成本分级

> 对应 PV-DIFF-004。区分复制成本，避免把"架构支持扩展"误读为"复制成本低"（依据 `SRC-IN-003`）。

| 复制类型 | 示例 | 成本 | 建议 |
|---|---|---|---|
| 同场景包换客户 | 古晶之外的其他灯具厂 | 低（换知识内容即可） | 近期主推，回应"扩大样本"诉求 |
| 同大类新行业 | 五金、建材等其他标准品制造业 | 中（需重评业务对象 / 知识结构） | 古晶验证成功后再做，预留调研周期 |
| 跨大类新场景包 | 服务型、渠道代理型等架构预留类型 | 高（接近重做一轮调研与产品定义） | 生存窗口期内不投入，长期视客户主动需求评估 |

## 5. 非目标与边界

- Phase1 不接入真实企业微信会话存档、真实飞书组织数据、真实 CRM/ERP/OA/工单系统。
- Phase1 不处理真实客户隐私数据、合同、报价、订单或生产会话。
- Phase1 不启用本地大模型推理、模型训练或生产规模向量索引。
- 未经人工确认，不调用外部付费 API、LLM API 或新增 Docker 镜像 / 依赖。
- 企业微信客户群“机器人自动对外回复”前提已被证伪，客户侧入口默认改为 H5。
- 系统不得为没有来源的事实、价格、交期、赔付、法律责任或售后承诺编造答案。

**长期定位（区分“暂缓但预留”与“明确不做”，2026-07-09 补充）**：

- **暂缓但预留**（愿景支持，后续阶段评估，不因 Phase1 不实现而视为长期不支持）：全渠道接入（PV-CAP-010）、真实业务系统集成（PV-CAP-011）、多租户 / 计费 / 监控（PV-CAP-012）、通用基线能力（PV-CAP-013~017）。
- **明确不做或强合规门槛**：见 §4.3 PV-NOT-001~005。其中企业微信会话存档 / 监控链路（PV-NOT-001）因强依赖企业微信认证与客户同意、与个人微信现实冲突，长期视合规条件评估，非近期目标。
