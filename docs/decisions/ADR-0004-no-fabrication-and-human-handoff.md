# ADR-0004 不编造与高风险转人工

> **定位：决策记录。** 本文记录数字客服回答边界和人工兜底原则。

## 状态

草稿，待人工确认。

## 背景

产品愿景要求减少漏回和统一口径，但售后、投诉、价格、交期、合同和赔付等问题若自动承诺，会产生业务风险。Demo 阶段也不能为了演示顺滑而编造事实。

## 决策

系统回答必须基于知识、规则、场景包或 Mock 数据。无依据、置信不足或高风险问题必须转人工或记录知识缺口。

## 理由

- 保护客户承诺边界。
- 让知识缺口成为运营改进入口。
- 避免 Demo 形成错误产品预期。

## 影响

- H5 必须展示转人工说明，而不是伪造答案。
- Web 控制台必须展示待跟进和知识缺口。
- 验证计划必须包含高风险和未知问题测试。

## 触发类型

- 投诉、曝光、赔付、合同、法律责任。
- 价格和交期承诺。
- 真实订单 / 项目数据不存在。
- 知识库无依据。
- 用户输入真实隐私或生产数据。
