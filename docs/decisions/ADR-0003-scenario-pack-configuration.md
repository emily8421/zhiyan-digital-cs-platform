# ADR-0003 场景包配置化

> **定位：决策记录。** 本文记录产品型 / 项目型客户场景包的配置化原则。

## 状态

草稿，待人工确认。

## 背景

项目需要同时支持产品型客户和项目型客户。若把客户叙事、规则和样例直接写入业务逻辑，后续很难扩展到更多客户类型，也无法追溯来源。

## 决策

场景包必须以配置或数据文件表达，包含意图样例、知识条目、规则条目、Mock 业务数据和演示问题。业务逻辑只读取场景包，不硬编码具体客户故事。

## 理由

- 支持不同客户业务形态复用同一平台。
- 便于追溯到 `docs/inputs/scenario-packs/*`。
- 支持后续 Web 控制台管理。

## 影响

- `docs/design/scenario-packs.md` 定义场景包结构。
- Sprint-1 需实现场景包加载与校验。
- 新增场景包时必须补来源和 Mock 标识。
