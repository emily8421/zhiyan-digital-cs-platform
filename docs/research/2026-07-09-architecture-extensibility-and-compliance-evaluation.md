### 2.3 合规缺口汇总（共性）

1. **缺 ID 体系**（最严重）：04 无 COMP-ID/MOD-ID/Flow-ID；05 无 TDR-ID/Risk-ID/RG-ID → §8 追溯矩阵无法用 ID 串联（违反 `document-lifecycle-rules.md` §5.4「REQ/NFR→Phase→COMP→MOD→Flow」）。
2. **缺关键章节**：04 缺 §9 检查表；05 缺 §3 依赖配置、§5 Phase 技术约束、§8 技术风险、§9 Readiness Gate。
3. **结构化不足**：约束、安全、待确认等多为 bullet/文字，非 doc-standards 要求的结构化表格（缺权威源/状态/验证入口列）。
4. **流程缺路径**：04 §5 仅成功路径，缺异常/降级/权限拒绝/外部不可用。
5. **待确认项结构不符**：非 §6.1 结构（缺 AI 建议/备选/取舍影响）。
6. **缺版本号**：05 技术栈未列具体版本。
7. **根因**：04/05 生成于 Phase1 早期（早于 v1.43.0 doc-standards 成型），与 DOC-C-007（design/* 未套用 v1.43.0 元信息）同源问题。

### 3.2 远期基线能力（PV-CAP-013~017）扩展点缺口——核心问题

04 目前只有**通用扩展占位**：§2 `future_systems` 节点 + §4 `adapters/` 层（未来 crm/erp/oa_adapter）+ `channel` 字段。**无针对具体远期能力的扩展点设计**：

| 远期能力 | 现状 | 扩展点缺口 |
|---|---|---|
| PV-CAP-010 全渠道接入 | channel 字段占位 | **缺 Channel Adapter Layer**（验签/去重/重试/限流/统一入出站/用户ID映射/授权边界）— 已登记 IN-C-005 / DOC-C-005 |
| PV-CAP-013 智能质检/合规监控 | audit_store 有审计日志 | 缺独立质检挂载点（audit 扩展 vs 独立服务未定） |
| PV-CAP-014 客户画像/跨渠道打通 | 无 | 缺画像/CDP 数据汇聚点 + 统一用户身份映射 |
| PV-CAP-015 工单全流程 | Handoff Service（转人工雏形） | 缺工单全流程扩展位（Handoff 扩展 vs 独立 Ticket 组件未定） |
| PV-CAP-016 RPA | 无 | 缺自动化流程挂载点（远期） |
| PV-CAP-017 行为触达 | 无 | 缺行为追踪/触达组件 |

> 注：按 `global-rules.md` §8.3「不提前写死远期细节」，这些**不应现在写详细设计**，但应在 04 标注**扩展点归属**（落在 adapters/ 还是独立组件），作为 Phase2+ readiness 参考。

### 3.3 场景包复制支撑

- ADR-0003（场景包配置化）支撑"换客户低成本复制"（同场景包换知识内容）。
- 但"新场景包接近重做"（业务对象/知识结构重设）的**架构含义未表达**：当前 Scenario Pack Service 假设固定业务对象结构（Product/SKU/Order vs Project/Milestone），跨大类新场景包需要业务对象可插拔，架构未说明该扩展点。

### 3.4 明确不做边界——OK

PV-NOT-001~005（企微存档、微信群机器人、高风险裁决、本地大模型、Boss特助）的架构边界均正确——04/05 不依赖这些能力，ADR-0001/0002/0004 + 05 §2 禁止项已覆盖。✅

## 4. 综合结论：Conditional Go

- **Phase1 已实现范围**：04/05 内容有效，支撑了 Demo 验收（AC-001~007、TC-001~016）。✅
- **差异化能力 + 明确不做**：架构基本支撑，边界正确。✅
- **合规性**：未严格套用 v1.43.0 doc-standards（缺 ID 体系、关键章节、结构化表格、readiness gate）。⚠️
- **可扩展性**：对愿景新增远期能力（PV-CAP-013~017）仅有通用占位，缺扩展点归属设计。⚠️

→ **Conditional Go**：可继续推进，但进入 Phase2 前建议补 P0 项（readiness gate / 技术风险 / Phase 技术约束），并将扩展点归属（channel-adapters 等）作为 Phase2 readiness gate。
