## 3. Phase3 进入标准核对

`docs/03-prd.md` 定义 Phase3 进入标准为“试点客户明确接口和授权”。当前尚缺以下条件，因此不建议直接进入真实集成实现：

| 条件 | 当前状态 | 判定 |
|---|---|---|
| 试点客户真实接口清单 | 未提供 CRM / ERP / OA / 工单 / 飞书项目接口清单 | 阻塞 |
| 数据授权与范围 | 未提供真实客户数据、订单、合同、联系方式处理授权 | 阻塞 |
| 沙箱或测试账号 | 未提供真实系统沙箱、测试账号、回调地址或白名单 | 阻塞 |
| 字段映射与主数据口径 | 订单、项目、客户、工单、员工身份字段未定义 | 阻塞 |
| 安全评审 | 凭据保管、脱敏、日志、权限、审计策略未完成 | 阻塞 |
| 验收客户与场景 | 未确认首个 Phase3 真实集成客户与验收场景 | 阻塞 |

## 4. 升级结论

结论：**Conditional Go → Phase3 准备规划；No-Go → Phase3 真实集成实施**。

可立即进入的范围：

1. 梳理 Phase3 真实集成候选清单、接口问卷和授权清单。
2. 设计真实系统适配层规范，但只写契约 / Mock / sandbox 骨架，不调用真实生产接口。
3. 明确首个试点客户的最小集成路径，优先只读查询，禁止先做写回生产系统。
4. 制定安全、隐私、凭据、日志、脱敏和审计边界。
5. 将 LLM 继续保持 `disabled` 或 Mock；真实 API / 自动答复启用仍需单独授权。

暂不解锁的范围：

- 不接真实 CRM / ERP / OA / 工单系统。
- 不接真实飞书生产组织数据或生产群事件回调。
- 不处理真实客户隐私、合同、订单、报价、联系方式或生产会话。
- 不启用真实 LLM API，不提交 API key，不发送真实客户数据给外部 LLM。
- 不把 Phase3 准备规划等同于 Phase4 多租户、计费、监控和产品化平台。

## 8. 建议下一步

1. 若接受本报告结论，下一任务优先新增 Phase3 真实集成接口问卷与安全边界清单。
2. 在用户提供首个试点客户系统清单前，不启动真实 CRM / ERP / OA / 工单代码接入。
3. 若要先做工程准备，只允许做 `docs/design/integration-adapters.md` 契约设计和 Mock / sandbox 骨架，不调用真实生产接口。
