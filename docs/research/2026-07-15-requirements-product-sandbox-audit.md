## 1. 评估摘要

当前需求链已经证明 Phase1 Demo 与 Phase2 MVP 技术闭环可用，但 `03` 的阶段路线图在 Phase2 与真实集成 Phase3 之间缺少一层“无真实数据但完整产品可试用 / 可演示”的阶段。用户的新目标不是简单增加 mock 样例，而是要形成一个可切换数据源、按场景包隔离数据、逼近真实业务使用的 Product Sandbox。

最关键的判断：

1. **不能直接把现有 Phase3 当作下一步**：当前 Phase3 定义为真实 CRM / ERP / OA / 飞书项目 / 工单集成，进入标准需要试点客户接口和授权；现状尚未满足。
2. **可以新增中间阶段**：新增 `Phase2.5 / Phase3A：Product Sandbox 可试用版`，用标准模拟客户、模拟知识库、模拟业务数据与演示运行态跑完整产品闭环。
3. **数据源模式应成为需求层概念**：`demo_sandbox`、`customer_sandbox_readonly`、`production_readonly`、`production_writeback` 应在需求 / PRD 中明确边界，而不是只留在实现代码里。
4. **模拟数据必须场景包内聚、真实数据隔离**：每个场景包绑定独立模拟数据集；演示运行态可重置；真实数据默认只读，未经授权不得启用。
5. **现有 Demo Sandbox 是基础但不够完整**：已有标准模拟业务数据、LLM Sandbox mock-first、演示彩排和 Console 标识；但现有场景包知识条目与业务记录规模仍偏小，且 `00-03` 未定义产品级试用验收口径。

## 4. 数据源模式建议

| 模式 | 用途 | 数据来源 | 当前是否允许 | 说明 |
|---|---|---|---|---|
| `demo_sandbox` | 销售演示、试用、培训、内部验收 | 场景包自带模拟数据 | 立即允许 | 默认模式；必须显式标识为模拟数据。 |
| `customer_sandbox_readonly` | 客户授权 PoC / 沙箱联调 | 客户测试库、沙箱 API、脱敏样例 | 条件允许 | 需要客户授权、字段映射、安全评审和只读权限。 |
| `production_readonly` | 真实上线早期只读查询 | 生产系统只读接口 | Phase3B 后评估 | 只读，不写回；失败时转人工或降级模拟但必须标识。 |
| `production_writeback` | 工单写回、状态同步、自动处理 | 生产系统写接口 | 当前 No-Go | 需要审计、回滚、权限和客户正式上线确认，建议 Phase4+。 |

需求层硬规则：

- 同一场景包必须绑定自己的模拟知识、模拟订单 / 项目 / 售后、模拟会话、模拟缺口和模拟摘要。
- 模拟数据是演示资产，不得写入真实客户数据空间。
- 演示运行态产生的会话、缺口、转人工记录可进入 demo runtime，但必须可一键重置。
- 切换到真实数据前必须满足授权、字段映射、安全评审和只读验证。
- UI 与 API 都必须暴露 `source_mode`、`scenario_pack`、`source_ref`、`mock` / `real` 等来源标识。
- 不得静默降级：真实数据不可用时若降级到模拟数据，界面必须明确显示当前为模拟数据。

## 6. Product Sandbox 验收建议

建议新增到 `03` §5 或后续 `09` 的验收口径：

1. 每个启用场景包至少有一套独立模拟数据包。
2. H5 / Console / API 均显示当前 `source_mode` 与 `scenario_pack`。
3. 使用模拟数据时，完整跑通：客户问答 → 订单 / 项目 / 售后进度查询 → 高风险转人工 → 缺口生成 → 知识入库 → Console 看板 → 通知记录 → 日报摘要。
4. 模拟数据切换 / 重置不影响其他场景包，也不影响真实数据配置。
5. 真实数据模式未授权时不可启用，只能显示 `Not configured / No-Go`。
6. 真实数据不可用时允许降级到模拟数据，但 UI 必须明确标识当前为模拟数据。
7. 虚拟客户资料包至少覆盖产品目录、FAQ、项目/订单/售后记录、历史会话和运营摘要。
