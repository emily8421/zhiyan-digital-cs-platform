> 来源 Batch：Batch 0 `docs/research/2026-07-06-template-proposal-audit-batch-0-overall.md`。

## 1. 评估摘要

本次 Batch 6 目标，是汇总 Batch 1~5 中反复出现的横切问题，判断是否需要独立模板提案，还是并入前面 Batch 的提案即可。

结论：建议**独立起草一个轻量横切规范提案**，但严格限定范围：只统一状态术语、检查表和跨文档引用口径，不重复 Batch 2 的技术风险矩阵、Batch 3 的 DB / API 契约状态、Batch 5 的 design readiness gate。

关键判断：

- Mock / 降级 / 默认关闭 / 候选 / 已验证 / 已启用 / 禁止等状态贯穿 `03`、`04`、`05`、`06`、`07`、`08`、`09` 与 `docs/design/*`，单独放在某一份文档标准中不够。
- 权限安全、隐私、真实外部服务、LLM / 向量、高风险售后承诺等都属于“横切事实 / 约束”，需要唯一权威源和引用同步。
- 现有项目文档整体口径一致：Phase1 Mock / Demo 数据、真实飞书 / 真实业务系统 / LLM 默认关闭、不处理真实客户隐私；但模板层面缺少一张横切检查表，帮助 AI 在审计和升阶段时识别状态混淆。
- 独立提案应服务于“统一术语和检查流程”，不应把各 Batch 的具体矩阵再写一遍。

## 5. 建议横切状态词典

| 状态 | 含义 | 禁止误写 |
|---|---|---|
| `已启用` | 当前 Phase 实际运行路径中默认使用 | 不得在未验证或未授权时使用 |
| `已验证` | 已通过指定范围验证，但不一定默认启用 | 不得等同于生产可用 |
| `Mock` | 仅模拟数据、payload、接口或状态流 | 不得写成真实业务系统接入 |
| `降级` | 替代真实依赖的低成本路径 | 不得写成目标能力已完成 |
| `默认关闭` | 能力存在设计或代码预留，但当前不开启 | 不得在当前 Sprint 默认启用 |
| `候选` | 方向性方案，尚未验证 | 不得进入实现计划，除非先做 Spike / PoC |
| `目标设计` | 未来结构或产品目标 | 不得写成当前实现 |
| `草案` | 契约或方案未冻结 | 不得对外承诺稳定兼容 |
| `禁止` | 当前阶段不得接入或实现 | 不得通过测试或演示绕过 |

| 检查项 | 触发条件 | 必查文档 | 通过标准 |

| 降级路径 | Docker、数据库、向量、外部服务不可用 | `04/05/09` | 有降级方案、触发条件和验证记录 |
| 权限安全 | Web 控制台、员工操作、外部接口、试点部署 | `05/07/design/09` | 有后端权限边界、审计和敏感数据说明 |
| 高风险能力 | 投诉、赔付、合同、价格、交期、LLM 自动答复 | `02/03/05/design/09` | 有转人工 / 不编造 / 人工确认兜底 |

## 9. 建议结论

建议保留独立提案：`_proposals/TEMPLATE-UPGRADE-cross-cutting-mock-security-standard.md`。

提案定位：

- 统一横切状态词典。
- 统一 Mock / 降级 / 权限安全 / 高风险 / 候选能力检查表。
- 统一状态变化触发的文档传播清单。
- 引用 Batch 2 / 3 / 4 / 5 的具体矩阵，不重复展开。
