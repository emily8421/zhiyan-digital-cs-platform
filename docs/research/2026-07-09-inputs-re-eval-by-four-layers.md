## 3. 逐份材料评估（口径落点）

### 3.1 SRC-IN-001 市场产品功能清单

- **核心价值**：本材料是判断"哪些能力属于通用标配"的**主依据**，因为它本身就是行业标配功能清单。
- **提取出的通用基线能力（建议归 A 层）**：
  - 基础对话：全渠道接入、LLM 意图识别、多轮引导、情绪识别、7×24。
  - 知识库：文档导入、在线文档 / 表格同步、跨渠道口径统一。
  - 业务闭环：调业务系统（改单 / 退款）、智能工单、RPA、未成交线索沉淀。
  - 数据运营：客户画像、行为推送、服务看板、智能质检。
  - 部署集成：SaaS / 私有化、开放 API、弹性扩容。
- **Boss 特助类能力的特殊处理**：会话存档 / 质检 / 绩效看板**强依赖企业微信认证 + 客户在企业微信上**，与知衍"兼容个人微信"差异化直接冲突 → 判为 **D 明确不做（近期）/ 严重降级**，而非通用基线。该判断由 SRC-IN-002 论证支撑。
- **关键洞察**：当前 `product-vision` §4 能力全景**未覆盖**智能质检、客户画像、行为推送、RPA、工单全流程等基线能力；客户对标竞品时易判为"功能不全"。

### 3.2 SRC-IN-002 通用解法的默认客户起点与古镇差距

- **核心价值**：这是**知衍差异化的"为什么"根基**。五维起点模型解释了知衍必须做的差异化：
  - 维度一 / 五（企微认证 + 客户在企微）→ 兼容个人微信的低门槛入口。
  - 维度二（知识未结构化）→ **代结构化知识**（服务型差异化）。
  - 维度三（无专职 IT）→ **免 / 低维护交付**（服务型差异化）。
  - 维度四（认知在具体效果）→ 老板看结果、按效果付费。
- **关键洞察**：其中"代结构化知识""免维护交付"是**交付 / 服务层面的差异化**，而当前 `product-vision` §4 的 PV-CAP 全是产品功能，**未体现这两项服务型差异化**——这是最大的反向校验缺口。

### 3.3 SRC-IN-003 场景包可复制性评估

- **核心价值**：对应"场景包复制"差异化。
- **关键洞察**：核心贡献是**区分两种复制成本**——"换客户不换包"（低成本）与"真正新场景包"（接近重做）；并警示"架构支持扩展 ≠ 复制成本低"。当前 `product-vision` PV-CAP-004 与架构"预留未来场景包"措辞**易被读成"扩展很轻松"**，本材料正是用来纠正该过度乐观判断。
- **建议**：愿景 / 架构补**复制策略与复制成本分级**；近期复制主推"同行业换客户"，新行业场景包须预留等价于重做一轮调研的周期。

### 3.4 SRC-IN-004 商业模式与定价参考

- **核心价值**：对应"古镇中小企业交付与定价适配"差异化。
- **关键洞察**：
  - 知衍走个人微信 + H5，**规避企业微信会话存档接口费（450 元 / 人 / 年）这一隐性持续成本**——反向强化 SRC-IN-002 的差异化逻辑（省下的不仅是认证门槛，还有持续成本）。
  - SaaS 订阅制存在结构性付费抵触 + 中小企业寿命短（约 2.5 年）→ 宜考虑**阶梯定价（验证期免费 → 转化期低价 → 深化期增值）或"买断 + 维护费"**，而非照搬互联网订阅逻辑。
- **反向校验**：当前愿景 / PRD **无商业模式 / 定价口径**。该内容属商业策略而非产品能力——是否进 `product-vision` 待人工确认（见 §6 IN-C-003）。

## 4. 整合能力地图（四层次）

> 核心产出。本表把 4 份材料散落的能力归类到四层次，"现状评估"列对照当前 `product-vision`。

| 层次 | 能力 | 现状评估（对照 product-vision） |
|---|---|---|
| **A 愿景必备基线** | 全渠道接入、LLM 意图识别、多轮引导、统一知识库（导入 / 同步 / 跨渠道）、智能工单全流程、客户线索沉淀、客户画像、运营服务看板、智能质检、业务系统集成（CRM / ERP / OA）、开放 API、弹性部署 | **部分覆盖**；质检、客户画像、RPA、工单全流程缺失 |
| **B 当前阶段实现**（Phase1 Demo） | H5 对话、规则意图路由、知识库问答、产品 / 项目场景包、Mock 进度查询、留资 / 转人工 / 高风险分流、知识缺口识别、飞书 Mock 通知、Web 控制台、日报 | 已实现（Sprint-1~5），与 Phase 边界一致 |
| **C 知衍差异化重点** | 兼容个人微信低门槛入口、**代结构化知识（服务型）**、场景包复制策略、不编造兜底 + 高风险转人工、老板看结果、**免 / 低维护交付（服务型）**、古镇交付与定价适配 | 部分散落；**两项服务型差异化（代结构化、免维护）几乎缺失** |
| **D 明确不做** | 真实企微会话存档 / 监控链路（强合规依赖，与个人微信冲突）、个人微信群机器人自动回复（合规风险）、高风险自动裁决、本地大模型训练、Boss 特助产品化方向（资源聚焦拆分，技术上可融合） | 多数已列入非目标 / 边界；**"企微存档"宜从"Phase 不接"明确为"长期视合规条件评估，非近期目标"** |

## 5. 对当前 product-vision 的反向校验（缺口清单）

> 对照 `docs/vision/product-vision.md`（最后更新 2026-07-03）：

1. **§4 能力全景缺"通用基线"层**：智能质检、客户画像、行为推送、工单全流程、RPA 未出现，对标竞品时显薄。（依据 SRC-IN-001）
2. **§4 无"差异化能力"独立分组**：代结构化知识、免维护交付、个人微信兼容、场景包复制策略未作为"为什么是知衍"显式表达，差异化价值被稀释。（依据 SRC-IN-002 / SRC-IN-003）
3. **措辞风险**：PV-CAP-010~012 把全渠道 / 集成 / 多租户堆到 Phase2~4，易被误读为"长期不支持"。需区分"暂缓但预留" vs "明确不做"。（依据 SRC-IN-001 / SRC-IN-002）
4. **缺场景包复制成本分级**（依据 SRC-IN-003）：架构"预留未来场景包"需补复制成本分级，避免过度乐观。
5. **缺商业模式 / 定价口径**（依据 SRC-IN-004）：是否进 `product-vision` 待定。
6. **缺 Channel Adapter Layer 设计**：全渠道接入的技术承载——架构已预留 `channel` 字段，但无正式渠道接入层设计文档。
