## 1. 产品目标

Phase1 的目标是用可本机运行的 Demo 证明“统一数字客服平台”可以覆盖产品型客户和项目型客户的基础客服闭环：客户 H5 提问、系统按场景包回答、无依据或高风险转人工、员工侧控制台查看待跟进与知识缺口、订单 / 项目进度通过 Mock 演示。Phase2 已完成 MVP 技术闭环验收。

Phase2.5 / Phase3A 的目标是形成 Product Sandbox 可试用版：在没有真实客户数据和真实业务系统授权的情况下，用场景包独立模拟数据、虚拟客户资料包和明确的数据源模式标识，演示接近真实产品使用的完整流程，并为后续授权真实只读数据接入预留门禁。

长期产品目标是把售前、售中、售后和运营沉淀为可配置、可接入、可复用的数字客服平台，但当前阶段不承诺真实业务系统集成或生产化交付。

## 4. Phase1 用户流程

1. 客户打开 H5 对话页，选择或默认进入一个场景包。
2. 客户输入问题，例如产品参数、项目进度、售后规则或投诉。
3. 后端识别意图并调用知识库、规则、Mock 业务适配层或转人工策略。
4. H5 展示答复、依据类型、Mock 标识或转人工说明。
5. 员工侧 Web 控制台查看新会话、待跟进、高风险、知识缺口和 Mock 通知。
6. 老板 / 运营查看日报摘要：会话数、自动回复、转人工、缺口和未结案。

## 5. 验收标准

| 编号 | 标准 |
|---|---|
| AC-001 | H5 能完成至少 6 类样例问题的问答或转人工。 |
| AC-002 | 产品型与项目型场景包均可演示，且不修改业务逻辑即可切换。 |
| AC-003 | 订单 / 项目进度查询明确标记 Mock，不连接真实系统。 |
| AC-004 | 高风险和无依据问题不编造答案，并生成待跟进或缺口记录。 |
| AC-005 | Web 控制台能展示会话、待跟进、缺口、通知和摘要。 |
| AC-006 | 日志和样例数据不包含真实客户隐私、token 或敏感业务数据。 |
| AC-007 | API 契约、DB 设计、开发计划、验证计划均能追溯到 REQ。 |
| AC-008 | 每个启用场景包至少有一套独立模拟数据包，覆盖知识、业务记录、历史会话、缺口和摘要。 |
| AC-009 | H5、Console 和 API 均显示当前 `source_mode`、`scenario_pack` 与来源标识。 |
| AC-010 | Demo Sandbox 可初始化 / 重置，且不影响其他场景包或真实数据配置。 |
| AC-011 | 真实数据模式未授权时不可启用，只能显示 `Not configured / No-Go`。 |
| AC-012 | 真实数据不可用时不编造业务结果；如降级模拟数据，界面必须明确标识当前为模拟数据。 |
| AC-013 | 使用模拟数据时可完整跑通：客户问答 → 订单 / 项目 / 售后进度查询 → 高风险转人工 → 缺口生成 → 知识入库 → Console 看板 → 通知记录 → 日报摘要。 |
| AC-014 | 虚拟客户资料包至少覆盖公司背景、产品目录、FAQ、订单、项目、售后工单、人员角色和历史会话。 |

## 6. 不做事项

- 不接入真实企业微信客户群自动回复或会话存档。
- 不接入真实飞书组织、真实 CRM/ERP/OA/工单系统。
- 不处理真实客户资料、联系方式、订单、合同、报价或生产会话。
- Product Sandbox 允许完整模拟真实业务结果，但必须标识为 `demo_sandbox`，不得宣称为真实生产数据或真实客户上线。
- 真实数据模式只做预留；启用前必须完成客户授权、字段映射、安全评审和只读验证。
- 不默认启用 LLM、外部付费 API、本地大模型推理或模型训练。
- 不实现生产级权限、多租户、计费、SLA 告警和可观测性。
