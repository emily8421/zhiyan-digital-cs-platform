## 1. 目标与范围

### 1.1 目标

- 为 Phase1 前端实现提供统一交互边界，避免编码阶段临时补页面、补状态或补承诺性文案。
- 串联客户侧 H5 与员工侧控制台，确保问答、转人工、知识缺口、Mock 查询和日报摘要形成可演示闭环。
- 明确所有 Demo / Mock / 高风险 / 隐私边界提示，避免用户误解为生产系统或真实业务数据。
- 将前端页面、用户路径、API 和验证用例建立可追溯关系。

### 1.2 覆盖需求

| 入口 | 覆盖 REQ | 覆盖功能 |
|---|---|---|
| H5 客户对话页 | REQ-001、REQ-002、REQ-003、REQ-004、REQ-005、REQ-006、REQ-008、REQ-013、REQ-016 | 客户提问、回复展示、Mock 标识、转人工提示、知识缺口提示 |
| Web 控制台 | REQ-006、REQ-009、REQ-010、REQ-011、REQ-012、REQ-013、REQ-016 | 会话查看、待跟进、缺口处理、通知记录、日报摘要、Mock 数据查看 |
| 共享前端能力 | REQ-007、REQ-014、REQ-015、REQ-016 | 场景包选择、API client、状态提示、本机 Demo 验证 |

### 1.3 Phase1 不做事项

- 不做正式登录、注册、支付、客户资料采集、客户身份识别。
- 不做生产级 RBAC、多租户、真实组织架构或真实员工通讯录。
- 不接入真实企业微信会话存档、真实飞书组织数据、真实 CRM / ERP / OA / 工单系统。
- 不上传真实合同、订单、报价、联系方式、客户隐私或生产会话。
- 不在前端伪造业务承诺；无依据、高风险或越权问题必须展示兜底和转人工提示。

## 3. 用户路径

### 3.1 客户创建会话并提问

| 步骤 | 前端动作 | API / 数据 | 成功状态 | 异常状态 |
|---|---|---|---|---|
| 1 | H5 加载，展示 DemoBanner | API-010 | 场景包可选，默认产品型 | 场景包加载失败时展示错误与重试 |
| 2 | 用户选择场景包 | `scenario_pack_code` | 选中态明确 | 无可用场景包时展示空状态 |
| 3 | 点击开始或首次发送前创建会话 | API-001 | 获取 `conversation_id` | 创建失败时不允许发送 |
| 4 | 用户输入问题并发送 | API-002 | 追加客户消息和系统回复 | 发送失败保留输入并允许重试 |
| 5 | 前端展示回答依据 | `answer_type`、`source_ref`、`mock` | 明确知识 / 规则 / Mock 来源 | 无依据时进入缺口或转人工提示 |

### 3.2 客户查询 Mock 进度

| 步骤 | 前端动作 | API / 数据 | 成功状态 | 异常状态 |
|---|---|---|---|---|
| 1 | 用户输入订单号、项目号或样例快捷问题 | API-002 | 后端识别进度查询意图 | 输入不完整时展示引导补充信息 |
| 2 | 系统回复进度信息 | Mock 业务数据 | 展示阶段、状态、更新时间、下一步 | 未匹配记录时展示“演示数据未找到” |
| 3 | 前端展示 MockBadge | `mock: true` | 明确“演示数据，不代表真实业务进度” | 不允许隐藏 Mock 标识 |

### 3.3 高风险问题转人工

| 步骤 | 前端动作 | API / 数据 | 成功状态 | 异常状态 |
|---|---|---|---|---|
| 1 | 用户输入投诉、索赔、法律、价格承诺等高风险问题 | API-002 | 返回兜底回答和 `handoff` | API 失败时展示“暂无法处理，请人工跟进” |
| 2 | H5 展示 RiskNotice 和转人工卡片 | `handoff.reason`、`handoff.status` | 文案不承诺赔偿、价格或时效 | 不渲染为普通确定性答案 |
| 3 | Console 待跟进出现记录 | API-004 | 员工可查看来源与状态 | 无记录时验收不通过 |

### 3.4 未知问题生成知识缺口

| 步骤 | 前端动作 | API / 数据 | 成功状态 | 异常状态 |
|---|---|---|---|---|
| 1 | 用户输入无依据或超范围问题 | API-002 | 返回缺口信息或转人工 | 不编造答案 |
| 2 | H5 展示“已记录知识缺口”提示 | `knowledge_gap` | 告知后续人工确认 | 不展示“已学会”或“已入库” |
| 3 | Console 缺口列表展示新记录 | API-005 | 运营可标记状态 | 无记录时验收不通过 |

### 3.5 控制台处理转人工

| 步骤 | 前端动作 | API / 数据 | 成功状态 | 异常状态 |
|---|---|---|---|---|
| 1 | 打开待跟进页面 | API-004 | 默认展示 `open` 记录 | 无记录时展示空状态 |
| 2 | 打开详情 | `handoff_id` | 展示来源会话、原因、风险等级、建议负责人 | 详情加载失败允许返回列表 |
| 3 | 更新状态 | API-004 PATCH | 状态变为 `processing` 或 `closed` | 更新失败保留原状态并提示重试 |

### 3.6 控制台处理知识缺口

| 步骤 | 前端动作 | API / 数据 | 成功状态 | 异常状态 |
|---|---|---|---|---|
| 1 | 打开知识缺口页面 | API-005 | 默认展示 `new` 记录 | 无记录时展示空状态 |
| 2 | 标记缺口状态 | API-005 PATCH | 状态可变为 `reviewing`、`accepted`、`rejected`、`closed` | 更新失败保留原状态 |
| 3 | 接受为知识候选 | API-006 | 创建候选知识条目 | 不自动承诺已生效 |

### 3.7 查看日报摘要

| 步骤 | 前端动作 | API / 数据 | 成功状态 | 异常状态 |
|---|---|---|---|---|
| 1 | 打开概览页面 | API-012 | 展示会话数、自动回复、转人工、缺口、未结案 | 摘要为空时展示“暂无演示数据” |
| 2 | 查看关键指标 | `DailySummary` | 指标可追溯到会话、转人工、缺口 | 不展示真实营收、真实客户或真实员工数据 |

## 4. 页面结构与组件

### 4.1 H5 页面结构

| 区域 | 组件 / 元素 | 展示字段 | 交互 |
|---|---|---|---|
| 顶部区 | DemoBanner、场景包标识、产品名 | 当前场景包、Demo 文案 | 可切换场景包；切换前提示会新建或重置 Demo 会话 |
| 消息区 | MessageList、SourceRef、MockBadge、RiskNotice | 客户消息、系统回复、回答类型、来源摘要 | 新消息自动滚动到底部；失败消息可重试 |
| 快捷问题区 | DemoQuestionList | 产品咨询、定制询盘、售后规则、订单进度、项目进度、高风险投诉、未知问题 | 点击后填入输入框，由用户确认后再发送 |
| 输入区 | TextInput、SendButton | 文本问题、发送中状态 | 空输入禁用发送；发送中禁用重复提交 |
| 状态区 | ConversationMeta、PrivacyNotice | 会话 ID、Mock / 隐私提示、最近意图 | 可折叠，默认展示关键提示 |

### 4.2 Web 控制台页面结构

| 页面 | 主要组件 | 展示字段 | 交互 |
|---|---|---|---|
| 概览 | SummaryCards、DailySummaryPanel | 会话数、转人工数、缺口数、未结案、摘要文本 | 刷新摘要，跳转到对应列表 |
| 会话列表 | FilterBar、ConversationTable、ConversationDetail | 状态、最近消息、风险等级、场景包、更新时间 | 筛选、查看详情 |
| 待跟进 | HandoffTable、HandoffDetail、StatusAction | 原因、建议负责人、风险等级、状态 | 更新为处理中或已关闭 |
| 知识缺口 | GapTable、GapDetail、GapStatusAction | 问题摘要、标签、状态、来源会话 | 标记 reviewing / accepted / rejected / closed |
| 通知记录 | NotificationTable、PayloadViewer | 事件类型、发送状态、payload、关联对象 | 查看 Mock payload，不真实发送 |
| 场景包 | ScenarioPackList、ScenarioPackDetail | 场景包编码、名称、样例问题、规则摘要 | 查看详情，不在 Phase1 编辑 |
| Mock 数据 | MockRecordTable、MockRecordDetail | 记录类型、外部引用、状态、更新时间 | 筛选与查看详情，不连接真实系统 |

## 5. 状态模型

### 5.1 H5 状态

| 状态 | 类型 | 说明 | UI 表现 |
|---|---|---|---|
| `conversationId` | string / null | 当前 Demo 会话 ID | 状态区展示；为空时提示先创建会话 |
| `scenarioPackCode` | string | 当前场景包 | 顶部展示，切换后影响样例问题 |
| `messages` | array | 本地消息流 | 消息区按时间展示 |
| `isCreatingConversation` | boolean | 创建会话中 | 禁用发送，展示加载 |
| `isSending` | boolean | 消息发送中 | 禁用发送按钮，展示发送中 |
| `lastIntent` | string / null | 最近识别意图 | 状态区或消息附属信息展示 |
| `handoff` | object / null | 最近转人工记录 | 展示转人工卡片 |
| `knowledgeGap` | object / null | 最近知识缺口 | 展示缺口提示卡片 |
| `error` | object / null | API 或网络错误 | 展示错误提示和重试入口 |

### 5.2 Console 状态

| 状态 | 适用页面 | 说明 | UI 表现 |
|---|---|---|---|
| `filters` | 列表页 | 当前筛选条件 | FilterBar 展示，支持清空 |
| `selectedId` | 列表 + 详情 | 当前选中记录 | 高亮选中行，详情区展示 |
| `isLoading` | 全部页面 | 数据加载中 | 骨架屏或加载提示 |
| `isUpdating` | 待跟进 / 缺口 | 状态更新中 | 禁用当前操作按钮 |
| `emptyReason` | 列表页 | 无数据或筛选无结果 | EmptyState 区分“暂无演示数据”和“筛选无结果” |
| `error` | 全部页面 | API 或网络错误 | ErrorState 展示重试入口 |
| `lastUpdatedAt` | 概览 / 列表 | 最近刷新时间 | 用于 Demo 时解释数据状态 |

### 5.3 通用状态展示规则

| 状态 | 触发 | 展示规则 |
|---|---|---|
| loading | 首次加载或刷新 | 不展示空白页面，使用加载提示或骨架屏。 |
| empty | 接口成功但无数据 | 明确是“暂无演示数据”还是“当前筛选无结果”。 |
| error | 网络、接口或契约失败 | 展示可理解错误，不暴露堆栈、token、内部路径。 |
| mock | 任一 Mock 数据或通知 | 必须展示 MockBadge，不得隐藏或弱化。 |
| risk | 高风险、越权、无依据 | 展示 RiskNotice，不渲染为确定承诺。 |
| readonly | Phase1 不支持编辑 | 按钮隐藏或禁用，并说明 Demo 阶段只读。 |

|---|---|---|---|

## 7. 文案与边界提示

### 7.1 必须出现的通用文案

| 场景 | 建议文案 |
|---|---|
| Demo 标识 | “本页面为本机 Demo，仅使用演示数据，不代表生产系统。” |
| Mock 数据 | “以下结果来自 Mock 演示数据，不代表真实订单、项目或售后进度。” |
| 隐私提示 | “请勿输入真实手机号、地址、合同、报价、订单截图或其他敏感信息。” |
| 高风险兜底 | “该问题需要人工确认，系统不会自动承诺赔偿、价格、交期或法律结论。” |
| 知识缺口 | “当前没有足够依据直接回答，已记录为知识缺口，需人工确认后再补充。” |
| 控制台标识 | “Demo 控制台：仅用于查看演示会话、Mock 通知和样例数据。” |

### 7.2 禁止文案

- 禁止写“系统已承诺赔偿 / 价格 / 交期 / 合同条款”。
- 禁止写“已接入真实订单系统 / 真实项目系统 / 真实飞书通知”，除非后续文档和人工确认已变更。
- 禁止写“知识已自动入库并立即生效”，Phase1 只能表达“候选 / 待确认”。
- 禁止把 Mock 进度描述为真实进度。
- 禁止在错误提示中暴露 token、服务器绝对路径、堆栈或客户敏感内容。

## 9. 响应式与可访问性

### 9.1 响应式要求

- H5 页面必须在手机尺寸和桌面浏览器中可读；手机优先展示对话、输入和关键提示。
- Console 以桌面浏览器为主；窄屏下可降级为纵向列表 + 详情折叠，不要求完整移动端运营体验。
- 关键操作按钮、风险提示、Mock 标识不得因窄屏被隐藏。
- 长文本回复、payload 和错误信息需要换行或折叠，避免破坏页面布局。

### 9.2 基础可访问性

- 输入框、按钮、筛选项和状态更新控件应支持键盘聚焦。
- 颜色不能作为唯一状态表达；Mock、高风险、错误和成功状态需有文字说明。
- 加载、错误、空状态需有明确文本，不只展示图标。
- 表格或列表中的关键字段应有可读标签，避免只用缩写。

## 11. Phase1 交互决策

| 决策项 | Phase1 建议 / 口径 | 依据 |
|---|---|---|
| 前端框架 | 采用 React + Vite + TypeScript。 | `docs/05-tech-spec.md` 已将 H5 与 Web 控制台均列为该建议栈，并规划共享 API client 和类型。 |
| H5 默认场景包 | 默认进入产品型场景包，同时保留场景包切换入口。 | 产品型咨询最适合作为首个 Demo 路径；场景包 API 已支持产品型 / 项目型列表与详情。 |
| H5 快捷问题 | 点击后填入输入框，由用户确认后再发送。 | 避免误发，便于演示时微调问题，也符合“不采集真实敏感信息”的边界提示。 |
| Console 导航 | Phase1 采用顶部 Tab，不做复杂左侧导航。 | 控制台 Phase1 仅覆盖概览、会话、待跟进、缺口、通知、场景包和 Mock 数据等基础列表。 |
| Console 列表详情 | 采用右侧详情栏。 | 适合列表连续查看与状态更新，比弹窗更利于对照上下文，比抽屉实现成本更低。 |
| 视觉规范 | Phase1 不单独补高保真视觉规范，仅保留轻量样式约定与 Demo / Mock / 风险标识要求。 | 当前目标是本机 Demo 闭环演示，视觉稿可在 MVP 或对外演示包装前另行补充。 |
| 移动端验收尺寸 | H5 以 375px 宽度作为手机可读性基准；Console 以桌面浏览器为主，窄屏只需可降级阅读。 | H5 是客户侧轻入口，必须手机可读；Console 是员工 / 运营演示入口，不要求完整移动端运营体验。 |
| 状态枚举 | 转人工使用 `open`、`processing`、`closed`；知识缺口使用 `new`、`reviewing`、`accepted`、`rejected`、`closed`。前端不得自行扩展。 | `docs/07-api-spec.md` 已给出 API-004 / API-005 的查询与更新状态示例，最终以 API 契约为准。 |
